# Petal Wanders — Flower Shop E-commerce

A small but complete e-commerce platform with three tiers:

| Tier | What it is | Tech | URL (local) |
|------|------------|------|-------------|
| **system** | Shared REST API — owns all data + business logic | Laravel 11 (PHP 8.2 / Apache) | http://localhost:8014 |
| **storefront + admin** | One Next.js app; storefront for customers, `/admin` for staff | Next.js 16 (App Router) | http://localhost:8015 |
| **database** | PostgreSQL | PostgreSQL 16 | localhost:8016 |
| **Adminer** | DB browser | Adminer | http://localhost:8017 |

The storefront and the admin portal **share one login** — authorization is decided by
**role** (`admin` vs `customer`). Both call the system API over HTTP.

API docs (interactive, generated by Scribe): **http://localhost:8014/docs**
OpenAPI + Postman snapshots live in [`docs/api/`](docs/api).

## Quick start

Requirements: Docker + Docker Compose (tested in WSL2).

```bash
cp .env.example .env          # ports + DB creds (already filled with dev defaults)
docker compose up --build -d  # builds and starts all four containers
docker compose logs -f system # watch the API boot (migrate + seed + docs)
```

First boot, the `system` container automatically: installs Composer deps if missing,
generates `APP_KEY`, runs migrations, seeds demo data, and generates the API docs.

Then open:
- Storefront → http://localhost:8015
- Admin → http://localhost:8015/admin (login required, admin role)
- API docs → http://localhost:8014/docs
- Adminer → http://localhost:8017 (server `db`, user `flowershop`, password `secret`)

### Seeded accounts

| Role | Email | Password |
|------|-------|----------|
| Admin | `admin@petalwanders.test` | `password` |
| Customer | `customer@petalwanders.test` | `password` |

Or register a fresh customer from the storefront login page.

## Architecture

```
Browser ──► Next.js (web :8015) ──HTTP──► Laravel API (system :8014) ──► PostgreSQL (db :5432)
                │                                                            ▲
                └── storefront (public)                                      │
                └── /admin (role: admin, guarded by proxy.ts)        Adminer (:8017)
```

- **Auth:** Laravel **Sanctum** Bearer tokens. `POST /api/auth/login` returns
  `{ token, user, roles }`. The web app stores it in a cookie and sends
  `Authorization: Bearer <token>` on each call.
- **Roles/permissions:** `spatie/laravel-permission`. Admin routes are protected by
  `auth:sanctum` + `role:admin`. The Next.js `/admin` area is additionally guarded
  server-side by `web/proxy.ts` (Next 16's renamed middleware).
- **API docs:** `knuckleswtf/scribe`, regenerated on each `system` boot.

### Key endpoints

| Method | Path | Access |
|--------|------|--------|
| `POST` | `/api/auth/register`, `/api/auth/login` | public |
| `GET` | `/api/products`, `/api/products/{slug}`, `/api/categories` | public |
| `GET/POST` | `/api/orders` | customer (auth) |
| `*` | `/api/admin/products`, `/api/admin/categories` | admin |
| `GET/PATCH` | `/api/admin/orders`, `/api/admin/dashboard` | admin |

Full reference: http://localhost:8014/docs

## Common commands

```bash
docker compose ps                         # status
docker compose logs -f web                # Next.js dev logs
docker compose exec system php artisan migrate:fresh --seed   # reset data
docker compose exec system php artisan scribe:generate        # regenerate docs
docker compose down                       # stop (keep data)
docker compose down -v                    # stop + wipe the DB volume
```

## Security follow-ups (before production)

- The auth token is stored in a JS-readable cookie for simplicity. For production,
  move it to an **httpOnly** cookie behind a Next.js BFF proxy route so it's not
  exposed to XSS.
- Add a production `web` Docker target (`next build` + `next start`) and a
  non-dev Laravel image (cached config/routes, `APP_DEBUG=false`).
- Tighten CORS (`system/config/cors.php`) to the real frontend origin only.

## Design reference

The UI is built to the **`Flower Shop Wireframes.dc.html`** Claude Design project,
imported via the `claude_design` MCP. The storefront (home, `/shop`, `/product/:id`,
cart, checkout) and the dark-top-bar admin (dashboard, sales, products + product editor,
customers, payment settings) follow the wireframe's dusty-blue system — Cormorant
Garamond / Mulish / JetBrains Mono, primary `#5a86a8`. Both the storefront and `/admin`
remain **one Next.js app** sharing a single login.

Backend additions that back the design: product **size variants** (S/M/L SKUs),
**related products**, **delivery options** + **bank-transfer** orders with
**receipt upload**, admin **Customers**, dashboard charts, and editable **payment
settings**. Checkout authenticates inline (sign in / create account) rather than placing
anonymous guest orders.
